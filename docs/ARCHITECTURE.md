# LIFESTYLE — архитектура продукта

Соцсеть живых встреч: люди находят встречи и сообщества по интересам, площадки и сообщества публикуют встречи.

## Роли

Аккаунт один на человека. Организация и сообщество — отдельные сущности, которыми пользователь управляет через роль.
Так владелец сети кафе ведёт несколько заведений с одного аккаунта, а права можно передать сотруднику.

| Роль | Кто | Что может |
|---|---|---|
| Пользователь | любой, кто вошёл по номеру телефона | смотреть ленту, записываться и платить, вступать в сообщества, писать в ленту сообщества, создавать сообщества, жаловаться |
| Владелец организации | пользователь, зарегистрировавший кафе, клуб, спортцентр | публиковать встречи от имени организации; **платные** — только после верификации |
| Владелец / модератор сообщества | создатель сообщества или назначенный им | публиковать **бесплатные** встречи от имени сообщества, модерировать ленту |
| Администратор платформы | команда LIFESTYLE | верификация организаций, разбор жалоб, блокировки |

## Ключевые бизнес-правила

1. **Деньги принимает только проверенная организация** (ТОО или ИП с БИН/ИИН, статус `verified`).
   Физлицо без ИП не может легально получать оплату за встречи. Платформа работает по агентской схеме:
   принимает оплату, удерживает комиссию и перечисляет остаток организации.
2. **Встречи сообществ в MVP бесплатные.** Если организатору сообщества нужно продавать места, он регистрирует ИП как организацию.
3. **Платная бронь держит место 15 минут** (`pending_payment`). Без оплаты бронь снимается по таймауту.
   Статус `confirmed` выставляет только бэкенд — по вебхуку Kaspi, не по ответу клиента.
4. **При отмене встречи** все брони отменяются, по оплаченным броням оформляется возврат.
5. **Размещение встречи организацией платное** (`LISTING_FEE_KZT`, сейчас 2 000 ₸): встреча создаётся в статусе
   `awaiting_payment` и попадает в ленту после оплаты. Сообщества размещают бесплатно.
   Рекомендация: со временем перейти на комиссию с проданных мест (10–15%) — предоплата отпугивает новые площадки.
6. **Подписка LIFESTYLE Pass** (`PASS_PLAN`: 5 000 ₸ / 30 дней, лимит 8 посещений): бесплатный вход на встречи
   с флагом `included_in_subscription`. Включить встречу в подписку может только проверенная организация и только платную.
   Организатору за каждое посещение подписчика платформа выплачивает компенсацию (например, 60% цены билета) —
   иначе площадкам невыгодно участвовать. Неявка без отмены за 12 часов списывает посещение.
7. **Каждый пользовательский контент можно обжаловать** (встреча, сообщество, пост, организация, пользователь).
   Это требование App Store (Guideline 1.2) и Google Play для приложений с пользовательским контентом.
   Нужны ещё блокировка пользователя и фильтр контента до публикации в сторы.

## Модель данных

Контракт клиента — `src/api/types.ts`. Схема БД (PostgreSQL):

```
users            id, phone (unique, E.164), name, city_id, interests[], created_at, blocked_at
organizations    id, owner_id → users, name, type, city_id, address, description,
                 bin (12 цифр), status (pending|verified|rejected), verified_at, created_at
communities      id, owner_id → users, name, description, city_id, interests[], telegram_url, created_at
community_members community_id, user_id, role (owner|moderator|member), joined_at   PK(community_id, user_id)
events           id, host_type (organization|community), host_id, created_by → users, city_id, interest_id,
                 title, description, venue, address, starts_at, duration_min, price_kzt, capacity,
                 status (published|cancelled), created_at
bookings         id, event_id, user_id, status (pending_payment|confirmed|cancelled),
                 via_subscription, expires_at, created_at                 UNIQUE(event_id, user_id) WHERE status <> 'cancelled'
posts            id, community_id, author_id, text, created_at, deleted_at      -- объявления (владелец/модераторы)
messages         id, community_id, author_id, text, created_at, deleted_at, deleted_by
message_media    id, message_id, kind (image|voice), storage_key, width, height, duration_ms, size_bytes
payments         id, user_id, purpose (booking|subscription|listing), target_id, amount_kzt, method (kaspi|card),
                 provider_payment_id, status (pending|succeeded|failed|refunded), raw jsonb, created_at
subscriptions    id, user_id, plan_id, status (active|cancelled|expired), started_at, ends_at, provider_recurring_id
payouts          id, organization_id, period, amount_kzt, status, items jsonb   -- выплаты за билеты и визиты по подписке
reports          id, reporter_id, target_type, target_id, reason, status, created_at
```

Счётчики (`booked_count`, `members_count`) отдаются денормализованно. Запись на встречу — в транзакции
с `SELECT … FOR UPDATE` по событию, иначе при гонке будет овербукинг.

## Чат сообществ

- Только для участников сообщества. Текст до 4 000 символов, до 10 вложений: фото (JPEG, сжатие на клиенте) и голосовые (AAC/m4a, на вебе — webm).
- Медиа грузятся напрямую в объектное хранилище по подписанному URL (`POST /v1/media` → `PUT uploadUrl`), API их не проксирует.
  Хранилище — S3-совместимое в дата-центре РК. Ограничения: фото до 10 МБ, голосовое до 5 минут.
- Доставка: WebSocket-шлюз (`/v1/ws`, событие `message.created` в канал сообщества) + push-уведомления (Expo Push → APNs/FCM)
  для тех, кто не в приложении. Клиент сейчас опрашивает список раз в 4 секунды — это остаётся запасным каналом.
- Модерация: удаление своих сообщений, модератор/владелец удаляют любые, жалоба на сообщение. Удалённые хранятся 30 дней для разбора жалоб.

## Платежи

- **Kaspi Pay** — основной способ. Сервер создаёт платёж, клиент открывает ссылку/QR Kaspi (`Linking.openURL`),
  статус приходит вебхуком `/v1/webhooks/kaspi`. Клиент не считает оплату успешной по своему ответу — только по статусу с сервера.
- **Карты Visa/Mastercard** — через эквайринг банка РК (Halyk ePay, CloudPayments KZ, ioka и т.п.).
  Номер карты вводится **в форме или SDK эквайера**, к нам приходит только токен — иначе нужна сертификация PCI DSS.
  Форма карты в приложении сейчас — демо: проверка Луна, срока и CVC, данные никуда не отправляются.
- **Подписка** — рекуррентный платёж (Kaspi или токен карты), продление за сутки до `ends_at`; при неуспешном списании — 3 попытки и уведомление.
- Возвраты: отмена встречи организатором → автоматический возврат участникам; отмена участником — по правилам оферты.

## Социальный слой

- **Друзья**: заявка → принятие (`friendships`), удаление из друзей. «Где был(а)» в профиле видно только друзьям.
- **Чёрный список** (`blocks`): заблокированный не пишет в личку, не шлёт заявки и не видит профиль заблокировавшего;
  его сообщения в чатах сообществ скрыты у заблокировавшего, он пропадает из списков «Идут». Блокировка разрывает дружбу.
- **Личные сообщения** (`conversations`, `direct_messages`): писать можно и друзьям, и не друзьям; для незнакомых — плашка
  с предупреждением о мошенничестве и кнопка «Добавить в друзья». Вложения как в чатах + карточка встречи («Поделиться»).
- **Статусы в личке**: одна серая галочка — отправлено (на сервере), две серые — доставлено (устройство получателя
  подтвердило приём: ack по WebSocket или открытие приложения), две зелёные — прочитано (получатель открыл диалог,
  `conversations.last_read[user]`). В чатах сообществ статусов нет.
- **«Печатает…»**: клиент шлёт `POST /v1/conversations/:id/typing` не чаще раза в 3 с, статус живёт 5 с;
  с WebSocket — событие `typing` в канал диалога без записи в БД.
- **Аватар**: квадратная обрезка на устройстве, сжатие до 320×320 JPEG, загрузка в хранилище, `PATCH /v1/me { avatarUrl }`.
- **«Важные»** — топ-5 друзей по числу личных сообщений за 30 дней; показываются первыми в списке друзей и в «Поделиться».
- **Рекомендации «Для вас»**: интересы ×3, друзья идут ×2, встреча моего сообщества ×2, продвижение ×1.5, ближайшие 48 ч ×0.5.

## Удержание и качество

- **Уведомления**: центр уведомлений в приложении + push (Expo Push → APNs/FCM, токены в `push_tokens`).
  Напоминание за 2 часа ставится и локально на устройстве. Типы: запись, напоминание, место из листа ожидания,
  сообщения, заявки в друзья, новая встреча по интересам, бонус за приглашение, просьба об отзыве.
- **Лист ожидания**: при отмене место уходит первому в очереди (бесплатная — сразу участник, платная — 30 минут на оплату).
- **Неявки**: отмена записи по подписке позже чем за 12 часов → `cancelled_late`, посещение списывается.
- **QR-чек-ин**: в билете `LS:<bookingId>:<code>`; организатор сканирует камерой или вводит 6-значный код.
  Чек-ин — основа выплат организаторам за визиты по подписке.
- **Отзывы**: только участник и только после начала встречи, один на встречу; рейтинг организации/сообщества — среднее.
- **Совместная запись**: до 5 мест одним платежом; по подписке — только своё место.
- **Реферальная программа**: промокод при регистрации, 1 000 ₸ бонусами обоим; бонусами — до 50% суммы.
- **Продвижение**: 3 000 ₸ за 3 дня закрепа в ленте и приоритета в рекомендациях.
- **Кабинет организации**: продажи, чек-ины, визиты по подписке, сумма к выплате, выгрузка участников в CSV (Excel/1С).
- **Карта**: тайлы OpenStreetMap для демо; в продакшене — 2GIS (покрытие РК, геокодинг адресов площадок).
- **2GIS, этап 1 (сделано)**: кнопка «Маршрут в 2GIS» на встрече и организации (`src/lib/dgis.ts`, `src/components/route-sheet.tsx`).
  В приложении — выбор способа (пешком / общественный транспорт / машина / такси) и deeplink
  `dgis://2gis.ru/routeSearch/rsType/<тип>/to/<lon>,<lat>`; если 2GIS не установлен — `https://2gis.kz/<город>/geo/<lon>,<lat>`.
  В браузере — сразу 2gis.kz. Ключ API не нужен.
- **2GIS, этап 2**: карта на MapGL JS API (веб — напрямую, мобильное — через `react-native-webview`) вместо OSM; ключ в `EXPO_PUBLIC_DGIS_KEY`.
- **2GIS, справочник**: Places/Geocoder API только с бэкенда (ключ не попадает в клиент) — подсказки адреса, геокодинг площадок.

## Авторизация

1. Вход по номеру телефона: SMS OTP, 4 цифры, TTL 5 минут, не больше 5 попыток и 3 отправок в час на номер и IP.
2. Ответ — JWT access (15 мин) + refresh (30 дней). На устройстве токен хранится в Keychain/Keystore (`expo-secure-store`).
3. Вход через Telegram — следующий шаг: Telegram Login Widget через WebView, подпись `hash` проверяется на сервере
   ботом `@LIFESTYLEK_BOT`. Аккаунты связываются по телефону.

## Требования Казахстана

- **Персональные данные граждан РК хранятся на серверах в РК** (закон «О персональных данных и их защите», ст. 12).
  Хостинг БД и бэкапов — в казахстанском дата-центре (PS Cloud, Kazakhtelecom, QazCloud и т.п.).
- Согласие на обработку персональных данных — явное, при регистрации, с версией документа в логе.
- Акцепт оферты — при оплате, с фиксацией `user_id`, времени и версии оферты.
- Платежи: Kaspi Pay (основной), карты Visa/Mastercard через эквайринг банка РК.

## Мобильный клиент

- Expo SDK 57, Expo Router (файловая маршрутизация), TanStack Query (кэш и инвалидация).
- `Stack.Protected` в `src/app/_layout.tsx` разводит три состояния: гость → вход; профиль не заполнен → онбординг; приложение.
- Без `EXPO_PUBLIC_API_URL` работает тестовый сервер на устройстве (`src/api/mock-api.ts`). Он повторяет бизнес-правила выше,
  поэтому UI можно делать и показывать до готовности бэкенда.
